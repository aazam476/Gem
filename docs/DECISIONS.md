# Decision Log

Choices made without asking, and why. Newest last.

| # | Decision | Why |
|---|----------|-----|
| 1 | **One FastAPI service** hosts the AI proxy and the gateway; the gateway is still a separate module (`gateway.py` pure, `ingest.py` sole writer) with its own endpoint and metrics. | Fewer moving parts for a hackathon; the trust boundary is the code path, not the process. Splitting into two services later is mechanical. |
| 2 | **SQLite (WAL)** as the only datastore; no Firebase/Supabase. | With a backend already in the loop, a cloud DB adds keys, latency and setup without adding a feature. UNIQUE constraints give exactly-once for free. |
| 3 | **Backend feeds Gemini output straight into validation**; the phone confirms a server-held `capture_id` and never sends numbers. | Otherwise "zero-trust frontend" is false: a client could submit any vitals. |
| 4 | **Idempotency key = client UUID per capture** (+ UNIQUE `capture_id`), not timestamps. | Timestamps collide and can't tell a retry from a new reading. Reusing the key across retries makes lost responses safe. |
| 5 | **HTTP 422 for out-of-range, 409 for duplicates** (with the original event in the body); not 406. | 406 is for content negotiation. 409+event lets clients treat a retry as success. |
| 6 | **Two-tier limits**: `hard_min/hard_max` reject (AI misread), `min/max` flag but store. | A genuine 210 mmHg is clinically important and must not be thrown away as a "retake". |
| 7 | **Cross-field rule** (systolic > diastolic) and **read-back confirmation** with deterministic wording. | Range checks can't catch 142-vs-148; the patient can. Read-back text is built from parsed numbers so what's heard is what's stored. |
| 8 | **Gateway dry run at capture time** in addition to the binding run at confirm. | The patient shouldn't be asked "is 900 right?". Both runs are timed and rejections audited. |
| 9 | **`readings` untyped at the HTTP layer** of `/ingest_vitals`. | Lets the gateway reject *and audit* hallucinated strings/booleans instead of a generic schema 422. |
| 10 | **Gemini default `gemini-3.6-flash`**, configurable; `thinking_level=low`, `temperature=0`, JSON schema output. | 1.5 Flash is retired. 3.6 Flash is the GA Flash ID listed by Google's docs at build time (a 3.7 ID appeared on a Cloud page but couldn't be verified). Low thinking keeps latency down. |
| 11 | **Images resized by the long edge** (768 px on device, ≤1024 px server guard), never forced square. | Square resizing distorts seven-segment digits. Normalized box coords stay valid. |
| 12 | **AI budget 8 s server-side, 15 s client-side**; overlay shown immediately, "still working" after 5 s. | Gemini + upload often exceeds 5 s; blocking immediately (not after 5 s) is what prevents double submits. |
| 13 | **Voice is streamed separately** (`GET /captures/{id}/speech`) instead of inlined in the capture response. | The JSON (box + text) returns as soon as Gemini finishes; audio streams in parallel; failure falls back to on-device TTS after 3 s. |
| 14 | **Offline voice = `expo-speech`** (on-device TTS), optionally replaced by pre-generated ElevenLabs clips via `scripts/generate_fallback_audio.py`. | If the network is the problem we can't call ElevenLabs. Bundling clips requires a key at build time, so the generated module ships empty. |
| 15 | **Mock vision when no `GEMINI_API_KEY`** (reported in `/health` and the portal header), `GEM_MOCK_AI=1` to force it. | Tests and the offline demo need deterministic AI. A dark frame returns "not found" so failure paths are demoable. |
| 16 | **One active protocol, single step**; activating one deactivates the rest. | Sane MVP; the patient app doesn't need a picker. |
| 17 | **Hard-coded patient `patient-demo-001`, session = UUID per app launch, no auth.** | Non-goal for the MVP (see SPEC §2). |
| 18 | **Expo SDK 57** (latest stable on npm at build time; 58 is still `next`). | Expo Go store builds trail new SDKs; the newest *stable* is the safest match. |
| 19 | **No Expo Router**, single `App.tsx` switch on `Platform.OS` (`?patient` on web previews the patient app). | Two screens don't need a router; the spec asks for conditional rendering. |
| 20 | **Camera passed via a callback ref** (`attachCamera`) instead of a RefObject in the hook result. | React Compiler lint (`react-hooks/refs`) flags RefObjects passed through props/objects during render. |
| 21 | **Contract tests mock the hooks** and render each screen per state. | Lets a restyle be verified mechanically without a device. |
| 22 | **`load_test.py` starts its own server** (temp DB, mock AI) unless `--url` is given; reports server-side validation time, an in-process micro-benchmark, and end-to-end latency. | Reproducible on any laptop; "microseconds" is only true for the pure function, so all three numbers are shown. |
| 23 | **No Stop hook** wired in `.claude/settings.json`; `scripts/check.sh` is the single check command instead. | A blocking hook in a shared repo can trap unrelated sessions; the script gives the same signal on demand. |
| 24 | Pitch, demo script and Devpost notes kept in `docs/PITCH.md`, out of `CLAUDE.md`. | Agents start each session cold; keep their instructions focused. |
| 25 | **Patient app replaced by the Gem assistant**; the capture/confirm screens were removed from the app. Backend `/captures`, `/ingest_vitals`, the gateway and the portal stay. | New direction from the product owner. The backend pieces are tested, cheap to keep, and may come back as a Gem "tool" (e.g. validating a reading Gem extracted). Removal is a follow-up decision for the owner. |
| 26 | **Context window held server-side; Gemini called per question with generateContent** (not the Live API, not the Interactions API). | Live API: audio-only output, no image output, 2-min audio+video sessions without compression, ~10-min connections, replaces ElevenLabs. Interactions API: every call generates a reply, so frames can't be appended silently. See ASSISTANT_SPEC §2. |
| 27 | **Gemini returns boxes; the server draws them** instead of using an image-generation model. | One model call, ~zero extra latency/cost, and the photo is never altered (important for medical devices and readings). |
| 28 | **Transcription by Gemini in the answering call** (WAV in the prompt; `transcript` in the JSON). | Speech-to-text in Expo Go has no on-device API without a dev build; a separate STT call adds a round trip. Gemini-only, as requested. |
| 29 | **Mic via `expo-audio` `useAudioStream` (PCM) + on-device VAD**, 16 kHz WAV upload. | Works in Expo Go SDK 57 (native); WAV avoids m4a/AAC container ambiguity with Gemini; VAD on-device means no audio leaves the phone until the user has finished a sentence. |
| 30 | ~~Mic muted while Gem is thinking or speaking~~ — superseded by #40 (only while thinking). | Prevents Gem answering its own voice (no echo cancellation in this path) and queued double questions. |
| 31 | ~~Only the 3 newest frames go to Gemini per question~~ — superseded by #38. | |
| 32 | **`gemini-3.8-flash`** for the assistant (`GEMINI_ASSISTANT_MODEL`), thinking low, temperature 0.3. | Newest stable Flash on the models page (Oct 2026); separate setting from the legacy reader. |
| 33 | **ElevenLabs audio cached twice**: player kept in RAM on the phone (replay = seek 0) and synthesized bytes kept per answer on the server. | Satisfies "store in RAM to avoid duplicate API costs" even if the phone's player had to be recreated. |
| 34 | **Idle = no frame and no prompt for 600 s** (reads don't count); purge is in-memory (frames, history, images, audio); 410 tombstones let the app reopen silently. | Matches the 10-minute requirement; nothing medical-adjacent is persisted. |
| 35 | **`change_score` returned per frame now** (32×32 grayscale mean abs diff). | Cheap, and it is one of the three signals the planned inactivity detector needs. |
| 36 | **Active protocol text injected as `<study_context>`** until researcher uploads exist. | Gives the portal an immediate effect on Gem; same slot the uploaded documents will fill. |
| 37 | ~~Typed-question box~~ — removed on request (#42). | Fallback when speaking isn't possible, makes the web preview usable (no AudioStream on web), and lets tests drive the full turn path. |
| 38 | **Visual memory: keep changed frames for 5 min and send all of them each question** (low res, newest 2 high res); Gemini picks `frame_id` and the server draws on that frame. | Required: "if I showed Gem a backpack a minute ago it should go back and box it". Dedup keeps cost proportional to how much the scene changes; frames-first ordering lets implicit caching reuse the prefix; per-image `media_resolution` (Gemini 3) keeps old frames at 280 tokens. |
| 39 | **Answer audio is downloaded to a cache file and played locally; the mic stream is stopped and the audio session switched to playback while Gem speaks.** (Fix after the first phone test: ElevenLabs returned 200 but nothing was audible.) | iOS's AVPlayer is unreliable with chunked, length-less HTTP audio, and with the mic open iOS stays in record+play mode where output can route to the earpiece. A local file + playback mode avoids both; a watchdog prevents a lost "finished" event from leaving the mic off. |
| 40 | **Barge-in:** the mic stays live while Gem speaks; the VAD switches to echo mode (learns Gem's voice level, needs +10 dB / 250 ms); speech start stops Gem; turn sent with `interrupted: true`; server drops echo transcripts (≥ 70 % of Gem's last answer). | Requested ("wait, no, the other chair"). No app-level echo cancellation exists in Expo Go, so a level gate + transcript check are the practical defences. |
| 41 | **Mic stream started once and kept running**; muting only ignores buffers; stall watchdog restarts it. Session audio mode = play-and-record on the loudspeaker. | Fixes "no listening after Dismiss": stopping `AudioStream` releases native resources, and restarting was unreliable. |
| 42 | **Frames paused while the answer screen is up; resumed on Dismiss. Typed-question UI removed** (`TurnIn.text` remains in the API for tests/tools). | Requested. A follow-up then refers to what the user was looking at, not the answer screen. |
| 43 | **History records exact marked boxes** and the prompt says to pick a different object when corrected. | Lets Gemini exclude the wrongly-marked chair. |
| 44 | **VAD requires voicing (pitch periodicity), not just loudness**; start hold 200 ms, barge-in hold 450 ms, minimum 350 ms of *voiced* speech per utterance, -45 dBFS floor. | First phone test: any background sound stopped Gem and triggered "thinking". Energy-only detection can't tell a clatter from a voice; an autocorrelation pitch check is cheap (~0.5 M ops/s) and rejects most non-speech. |
| 45 | **iOS barge-in uses the file recorder's level meter while Gem speaks**, then hands over to the stream with the recorded start of the speech as a seed; the stream is restarted the moment Gem stops. | Phone test: interrupting only worked "a few seconds after ElevenLabs stops". Cause found in expo-audio's iOS `AudioStream` (sets `.record` category, dies on session change, no restart handling). The recorder supports play-and-record in Expo Go. Trade-off: barge-in on iOS is level-based (no voicing check) for the first ~0.4 s; the full utterance still goes through the voiced-speech check and the server echo filter. |
| 46 | **iOS barge-in calibrates only on audible playback** (`onAudible` from AnswerAudio), tracks Gem's level continuously, margin 10 dB. | Phone log: `user interrupted Gem at 823 ms (echo -48 dB)` with nobody speaking — the echo was measured on room silence during the answer download, so Gem's own voice looked like the user. |
| 47 | **Inactivity = no movement (accelerometer/gyroscope), speech, scene change (≥ 0.08), tap or Gem activity**; idle at 1 min pauses frames; expired at 10 min ends the session from the app; any signal wakes, a new session opens lazily. | Requested. Accelerometer/gyroscope need no permission (DeviceMotion would on iOS). Scene change can only wake while frames flow, so motion/speech are the wake signals while idle. |
| 48 | **Study documents attach to a protocol** (the existing study unit) rather than a new "study" entity; the session snapshots the protocol active at its start. | Smallest change that gives researchers the feature; per-patient study assignment is a later step. |
| 49 | **Documents persisted (SQLite + `backend/uploads/`)**, unlike Gem's RAM-only session context. | They are researcher materials, not patient data, and must survive restarts. |
| 50 | **Gemini Files API + implicit caching via a documents-first prompt**, not explicit context caches. | Files API avoids re-sending PDF bytes; explicit caches need ≥ 4k tokens, TTL management and fix the system prompt; a stable prefix gets implicit caching for free. Inline bytes are the fallback. |
| 51 | **JSON base64 uploads** (no multipart). | Avoids adding `python-multipart`; 20 MB files fit; the web portal reads files via `expo-document-picker` (`base64: true`). |
| 52 | **Inactivity timings are researcher settings** (`GET/PUT /settings/assistant`, SQLite `app_settings`), delivered to the app in `POST /sessions`; the server purge uses the same value. Applied to new sessions only. | Requested ("make it adjustable from the portal"). Snapshotting per session avoids timings changing under a running conversation; one global setting until studies have per-patient assignment. |
| 53 | **UI rework (apple-design / animate-expo skills):** camera-first screen with one glass status capsule, one bottom message at a time, and an answer *sheet*. Removed from the patient UI: frames sent/remembered, change score, "Mic on/off" (mic shown only when it fails). | Patients need what Gem is doing and what it said, not diagnostics. Diagnostics stay in the hook (`frames`, `micActive`) and in backend logs. |
| 54 | **Motion:** Reanimated 4 (+ worklets, gesture-handler, all in Expo Go). Answer sheet = spring entry `{300 ms, damping 0.8}`, 200 ms exit, drag-to-dismiss with velocity projection and rubber-banding; press scale 0.97 / 120 ms via Reanimated CSS transitions; status changes 180 ms; reduced motion → fades. No looping pulse on the camera; no motion in the portal (used many times a day). | Skill rules: frequency gate, transform/opacity only, springs for gestures. The Dismiss button stays the primary exit (UI contract: no required precision gestures). |
| 55 | **No haptics** in the Gem app. | iOS suppresses haptics while the audio session is recording, and Gem's mic is always on; a vibration could also be picked up by the VAD. |
| 56 | **Light/dark mode follows the system setting** (no in-app switch): `useTheme()` picks a light or dark palette from `useColorScheme()`; `app.json` `userInterfaceStyle: automatic`. Dark palette uses Apple's dark grouped colors, with a lighter `primaryText` (#4C9AFF) for links/icons since the button blue is too dark as text on dark surfaces. Camera chrome is dark in both modes; the status bar stays light over the camera. | Requested. Following the system is the platform convention and needs no stored preference; all text colors are tested for WCAG AA in both palettes. |
| 57 | **ElevenLabs synthesis starts when the turn is answered**, as a background task on the server, instead of when the phone requests `/speech`. The endpoint awaits that shared task (shielded from client disconnects) and retries a failed one. | Gem's voice is made while the image is drawn and the answer travels to the phone, which shortens the gap between the text appearing and hearing it. Costs nothing extra: the app fetches every answer's audio anyway. |
| 58 | **Study documents are edited only for the active protocol** (the "For: / Switch to" protocol picker was removed) and the card sits under Protocols. | Researcher feedback: the picker looked like a second Activate button. Activate already decides what patients and Gem use; to prepare documents for another protocol, activate it first. |
| 59 | **Barge-in removed** (supersedes 40, 45, 46): the mic is ignored while Gem thinks and speaks, plus 300 ms after; iOS stops the stream during Gem's voice and restarts it as soon as Gem finishes; the iOS recorder/meter path, VAD echo mode and the `interrupted` turn flag are gone. The server echo check stays. A dev-only mic health log prints every 5 s. | Requested after a phone test where Gem stopped registering speech: the barge-in path (stream stopped, second recorder, seeded restart) was the most fragile part of the mic and couldn't be made reliable without platform echo cancellation. "Speak when Gem is quiet" is simple and predictable. |
| 60 | **Camera frames captured at ~1080p** (`pictureSize`, preferring 1920x1080 then 1280x720, from the camera's own list) instead of expo-camera's default "Photo" preset. | Phone test: the preview jittered/froze every second. The default preset takes a full-resolution (12 MP+, HEVC) still per frame; Gem only uses a 768 px copy. |
| 61 | **The answer player moves the mic aside before playing** (`AnswerAudio.setBeforePlay(mic.standBy)`), instead of a React effect stopping the iOS stream after "speaking" renders. | Phone test: "Read again" was silent. A cached replay starts instantly, so the effect's `stream.stop()` landed mid-playback and cut the audio; the first answer only worked because its download gave the stop time to finish first. A watchdog resumes listening if audio never actually starts. |
| 62 | **Each replay gets a fresh audio player on the cached MP3 file**; a player that fails to start is released but the file is kept. | Phone test: every other "Read again" fell back to the phone's voice, then silence. A player that had played to the end was rewound without waiting and started from the end, so it never reported "playing"; the fallback then deleted the cached file. A new player on a local file is cheap and always starts at 0. |
| 64 | **User mute** is part of the assistant state (`userMuted`, `SET_MUTED`) and folds into `isMicMuted`, so it uses the same "ignore buffers + reset the detector" path as Gem thinking/speaking; muting while `hearing` returns to `listening`. Frames keep flowing; the mute is not persisted. Button: round glass, top right, rendered above the answer sheet (which now stops below it). | Requested for demos. Reusing the existing mute path means a half sentence can never be sent (the detector is reset on every mute change) and needs no new audio-session handling. |
